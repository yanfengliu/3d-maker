# Form Foundry

## Editor and inventory

The studio targets desktop browsers with WebGL 2. It opens with the full inventory beside an editable Relay Drone. Collections filter studio originals, public PolyFork models and browser-local saves. Categories filter all three sources. Search, previous and next controls, and a page-number field span the filtered inventory. Selecting a card changes the editor while preserving the inventory view. The procedural catalog ships 106 originals (88 objects and 18 humanoid characters across buildings, characters, vehicles, animals, terrain, props, handheld items, and attachments) with append-only named model variations stored alongside each base template so alternative looks and structural configurations remain selectable for different situations (`?asset=<id>&variation=<variation>`). Appearance controls change body and accent colors. Geometry controls change scale, width, surface detail, and standard or HD quality. HD adds authored components, smoother curved geometry and material detail. Each original has animation clips. Characters use skinned meshes with stable 19-joint rigs at both qualities.

Animated assets start playing when opened. Properties and Animation are both visible beneath the viewport as soon as a model loads. The Animation section lists and searches named clips. Choosing a clip starts it immediately. Space toggles playback in the workspace and preserves normal text entry and dialog controls. Play all clips advances through the full repertoire and wraps to the beginning. Pausing and editing an original keep its current clip and timeline position. For a compatible rig, the studio adds the packaged CC0 humanoid repertoire when the model opens or exports. All original character rigs use the same repertoire in the standalone SDK. Custom embedded tracks retain their order. The studio previews clips, speed and time, keeps low or stretched poses framed above the floor grid without disturbing the user’s orbit or exported motion, renders with a real-life perspective camera by default alongside a persisted Perspective / Orthographic projection toggle (shared across localhost ports via cookie and `localStorage`), supports camera presets and orbit, and changes the floor grid or wireframe overlay independently of the exported asset. The saved collection stores starter recipes in localStorage. Imported local files and edit metadata share an IndexedDB transaction. For a PolyFork import, the inventory retains the canonical source reference and retrieves the mesh when reopened. Saved assets belong to the browser and origin. Download a recipe or GLB to move work between machines.

## PolyFork and imports

**Remix** starts a new draft from the displayed model and its current edits, including unsaved changes. It preserves camera, animation and playback. The new draft gets its own ID on first save. Later saves update the copy. The same action works through the agent API as `remix(name?)`.

**Model colors and interactive parts** expose the model’s authored capabilities locally. For PolyFork imports, the studio fetches the free public detail and colorway metadata alongside the GLB so rigged hinges and slides (such as a shop door swinging 0–80°), detachable parts (such as a planter, display stand or lantern), night emissive zones, declared decal areas, curated colorway presets and named color zones are immediately editable in the inspector and viewport toolbar (including a click-to-pick surface eyedropper). The procedural originals publish their own movable and detachable parts in the same schema (saved recipes persist recipe fields; live poses and detachable visibility on originals apply to the preview and exported GLB). The browser inventory stores color overrides, part poses, hidden parts, night mode, decal preview text, and a cached capability snapshot alongside each saved PolyFork source so edits survive reopening even if metadata is temporarily unreachable.

**Self-describing GLB export, hierarchical composition, and SDK controllers** preserve these capabilities when models move into scenes, multi-piece assemblies, or AI workflows. Every exported GLB embeds a versioned `extras.formFoundry` manifest on its root node (`riggedParts`, `detachableParts`, `nightZones`, `decals`, `params`, `dimensions`, `physics`, `ik`, `colliders`, `clearanceZones`, `surfaces`, `children`, `clips`, and current state), retains hidden detachable subtrees so `state.hiddenParts` can restore and re-show them, and can optionally bake standard glTF `AnimationClip`s for rigged parts. `studio-sdk.js` exports `inspectAsset`, `createAssetController`, `composeAsset`, `createCompositeController`, `validateComposite`, `synthesizeRigClips`, `deriveSpatialMetadata`, `deriveIkMetadata`, `resolveModelParams`, `mergeStaticParts`, `resolveAssetVolumes`, `obbOverlap`, `validateScenePlacement`, and `checkRiggedSweep`. See [hierarchical asset composition](composition.md) for combining multiple assets while keeping child knobs, concurrent animations, and physics coupling laws intact.

The inventory requests free metadata and thumbnails from PolyFork by category, search term and page. If the service is unavailable, originals and local entries remain browsable and a retry control appears. Selecting a result opens its GLB from the publisher. The importer keeps embedded materials, mesh hierarchy, skeletons and clips. Name, tint, scale, and height are editable. White restores the original paint. The exported scene carries source credit and edit details for a PolyFork import. The local dataset and download scope are recorded in [the dataset guide](../dataset.md).

## Agent and game interfaces

A versioned JSON recipe is the source for an original asset. Agents can read `catalog.json`, `agent-schema.json` and `llms.txt` at the app root. The browser exposes `window.forgeStudio` for reading and applying recipes, saving, listing inventory, playing clips, editing imported assets and exporting binary glTF. The same validated recipes build ordinary three.js Groups in the standalone `studio-sdk.js` module. The README contains a working game integration.

The AI tools panel accepts a structured recipe or a text edit. The natural-language editor uses a supported Chrome installation’s on-device language model when available. The user can explicitly enable a downloadable model. Other browsers support a documented local command vocabulary. The editor identifies which engine applied the edit. Imported GLBs support named-region prompts and JSON settings edits in AI tools as well as the inspector and import edits API.

## Capture contract

`?asset=field-pilot` selects a starter by ID. `?shot=1` starts at rest. Add `&view=Front`, `Back`, `Left`, `Right`, `Top`, `Bottom`, `Side`, or `Perspective` for a fixed preset, `&grid=0` to hide the floor grid for clean silhouette and underside inspection, and `&noui=1` for a full-frame model. The renderer preserves its drawing buffer and sets `window.__shotReady` after five rendered frames. The default perspective shows the model from above its front-right corner.
